# SEO 与真人化写作规则

> 用途：给 Pace Notes 和 `blog-agent` 做发布前审查。目标不是骗搜索引擎，而是写出更有用、更容易被搜索和 AI 答案引擎理解的内容。

## 核心原则

- 先服务读者，再考虑搜索。Google Search Central 明确强调“实用、可靠、以用户为中心”的内容。
- 每篇文章回答一个明确问题：谁该看、能解决什么、读完能做什么。
- 每篇文章要有可复查来源、实际判断和限制说明，不能只是链接搬运。
- description 是搜索结果摘要候选，不是任务说明。
- 标题和首段要像人写给人看的，不像自动化流水线日志。

## 标题规则

好的标题需要同时满足：

1. 有明确主题词：OpenClaw、n8n、MCP、Cloudflare Pages、AI 生图等。
2. 有读者收益：能上手、避坑、对比、部署、成本、限制。
3. 不堆关键词，不使用夸张词。
4. 每日资讯可以带日期，但不能只靠日期成立。

示例：

- 差：`2026-05-08 普通人可用AI工具速览`
- 好：`5 个今天就能上手的 AI 工具：生图、短视频和免费模型 API`
- 差：`2026-05-08 下午速览：整理 5 个...`
- 好：`今天这 5 个 AI 工具值得试：做图、短视频、免费模型 API`

## Description 规则

- 70-120 个中文字符优先。
- 写成读者会看到的摘要，不要写“本文整理了/综合 N 条/抓取时”。
- 必须包含一个具体收益或判断。
- 不要把内部流程词放进去：`多源验证`、`抓取记录`、`任务`、`自动化`，除非文章主题就是流程。

## 首段规则

首段要回答：今天为什么值得看？

每日资讯首段不要写成“下面整理 X 条”。应该给出人的判断：

- 今天热点集中在哪个方向？
- 对普通用户/开发者有什么影响？
- 哪些只是新鲜，哪些值得跟进？

## 每日资讯文章结构

每条信息保留 4 个要素：

1. 它是什么
2. 适合谁
3. 为什么现在值得看
4. 限制/风险/成本

来源链接放在每条下面，优先官方源；非官方评测只能做补充。

## Evergreen 文章结构

长期搜索文章优先写：

- 适用场景
- 最小可行步骤
- 配置/命令
- 常见错误
- 成本与限制
- 更新记录

这类文章比每日资讯更适合放在首页或精选位。

## 首页与精选规则

- `featured: true` 只给长期有价值的文章。
- 每日资讯默认 `featured: false`。
- 复盘/变现类文章可以存在，但不应长期压过教程类文章。
- 首页应优先展示“能解决问题”的内容，而不是站点内部战略。

## 去 AI 化发布检查

发布前删掉或改写：

- “本文整理了”“下面是”“总的来说”“值得注意的是”过度模板句。
- “抓取时”“综合 5 条”“多渠道搜集”这类内部流程词。
- 每段都重复“为什么有用/注意点”的机械结构。
- 没有个人判断的纯摘要。
- 过度安全但无信息量的免责声明。

## AI 搜索/答案引擎友好写法

- 明确事实边界：价格、版本、额度写“截至 YYYY-MM-DD”。
- 使用稳定小标题，便于引用。
- 每个工具/项目都给原始链接。
- 把判断写清楚：推荐谁用、不推荐谁用。
- 保留更新日期和变更记录，便于后续刷新旧文。

## 发布前硬门槛

任一命中则不发布：

- title 或 description 像内部任务说明。
- 没有来源链接。
- 只复述来源，没有自己的判断。
- 承诺收益、免费、排名或能力但无法验证。
- 首页预览读起来不像真人写的。
