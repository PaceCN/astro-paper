# 博客运营说明

## 站点定位

中文个人开发者实战手册：AI 自动化、自托管运维、低成本独立博客。

## 栏目

- `ai-automation`：n8n、MCP、Agent 工作流
- `self-hosting`：VPS、Cloudflare、Docker、备份、安全
- `astro-blog`：AstroPaper、SEO、独立博客建设
- `income-log`：成本账、变现复盘、服务器维护成本

## 发文节奏建议

- 每周 1 篇深度教程，或 2 篇短教程。
- 每月更新 5 篇旧文，检查版本、价格、链接是否过期。
- 联盟/赞助内容必须披露，链接按需使用 `rel="sponsored nofollow"`。

## 长期子 Agent 建议

需要，但不建议全自动发布。推荐职责：

1. 每周选题和关键词研究
2. 生成草稿和检查清单
3. 技术验证、链接检查、SEO 检查
4. 提交 PR 或草稿，最终由人审核合并

## 首阶段目标

先做 20 篇长期搜索型实战文章，建立可信度和入口，再考虑广告或赞助。

## 每日自动化发布计划

- 09:00（北京时间）：发布《GitHub每日热点与AI资讯速览》
  - GitHub 升星最快前 5 个项目
  - AI 最新/最热资讯 3 条
- 16:00（北京时间）：发布《普通人可用AI工具速览》
  - AI 生图、AI 生视频、免费/低成本模型 API、普通人可直接用的工具与方法，共 5 条

### 自动发布门禁

1. `blog-agent` 负责搜集、交叉验证、写初稿、自审和润色。
2. 用户已授权每日自动发布；`blog-agent` 自审 + format/lint/build 通过后可发布。
3. `main` agent 事后监督：检查状态文件、git diff、线上页面和内容质量。
4. 如果构建、来源验证、标题/摘要质量或内容可信度不足，保留 `draft: true`，不发布。
5. 每个阶段更新 `docs/AUTOMATION_STATUS.md`，作为长任务心跳。

## 内容质量与展示规则

### 首页/列表排序

- 每日资讯类文章可以发，但不能长期压住核心 evergreen 文章。
- 需要优先展示“可长期搜索、可解决问题”的文章，例如部署教程、OpenClaw 自动化实践、n8n/MCP 实测。
- 战略/复盘类文章如“覆盖服务器成本”可以保留，但不应长期作为首页最显眼内容；后续可降权或改为 `income-log` 专栏入口。

### 标题与摘要

- 标题写给读者，不写给任务系统。
- 禁止使用“整理/速览：整理/收集/本文整理了……”这类内部任务口吻。
- description 必须像真实文章摘要，不要像提示词或任务说明。
- 示例：
  - 差：`2026-05-08 下午速览：整理 5 个普通人今天就能尝试的 AI 生图...`
  - 好：`这 5 个 AI 工具今天就能上手：做图、生成短视频、调用免费模型、让浏览器帮你整理网页。`

### 每日资讯文章

- 首段要有人的判断：今天为什么值得看，而不是“下面整理 N 条”。
- 每条都要说明：它是什么、适合谁、有什么限制、为什么今天值得关注。
- 不要夸张，不要“最强/震撼/颠覆”，除非来源和事实足够支撑。
- 来源链接保留在每条后面，方便搜索引擎和 AI answer engine 复查。

### 去 AI 化检查

发布前删除这些痕迹：

- “本文整理了”“以下是”“总的来说”“值得注意的是”过度模板化表达。
- 重复的三段式：“它做什么 / 为什么有用 / 注意点”可以保留结构，但要让句子自然。
- 过度保险的空话，例如“价格变化很快，请自行确认”可以简短保留，不要每段都重复。
- 看起来像内部工作流的词：`抓取时`、`任务`、`综合 5 条`、`多源验证`，除非是在幕后文档中。

## SEO 与真人化写作

详细规则见 `docs/SEO_STYLE_GUIDE.md`。每日自动发布前必须检查标题、description、首段、来源链接和首页预览，避免文章像内部任务说明或 AI 批量摘要。


## 日期规则

- 文章排序、首页、列表、归档、上一篇/下一篇和 RSS 顺序都以 `pubDatetime` 为准。
- `modDatetime` 只表示内容更新，不用于覆盖发布时间或 RSS `pubDate`。
- 页面展示稳定发布时间；只有当 `modDatetime > pubDatetime` 时额外展示更新时间。
- SEO `datePublished` 使用 `pubDatetime`，`dateModified` 可使用 `modDatetime`。
- 发布前运行 `corepack pnpm run validate:dates`，检查缺失/无效日期、更新时间早于发布时间、异常重复更新时间、过远未来日期和文件名日期偏差。
