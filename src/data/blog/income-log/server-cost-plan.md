我做这个站，有一个很朴素的目标：以后最好能让内容覆盖服务器和工具成本。

但这件事不能从“先挂广告”开始。小博客早期流量少，广告收入很薄，还会把阅读体验弄得很碎。更麻烦的是，一旦为了广告去追热点、堆文章，博客最重要的东西就没了：可信度。

## 为什么不一开始做 AdSense

AdSense 不是不能做，只是不适合太早做。

早期博客通常有三个问题：文章少、搜索入口少、读者信任还没建立。这个阶段挂广告，大概率收益不够看，还会让页面显得很廉价。

更糟的是，广告会悄悄改变写作方向。你会更想写容易带流量的标题，而不是写真正解决问题的教程。短期可能多几个点击，长期会把站点做空。

## 更现实的顺序

### 先写真实教程

技术博客最稳的入口，还是能解决问题的文章。

比如：

- Cloudflare Pages 部署 AstroPaper
- VPS 初始化和安全加固
- n8n 自部署、备份和恢复
- MCP 工具链配置
- Pagefind 中文搜索索引问题
- 静态博客接 Search Console 和 sitemap

这些内容不一定爆，但生命周期长。只要步骤清楚、版本写明、坑讲透，几个月后仍然有人会搜到。

### 再放合规推荐

当文章里确实用到某个服务，可以放 referral 或 affiliate 链接。

但要守住几条线：

- 自己真的用过，或者明确说明只是可选方案
- 不夸大收益
- 不暗示“点这个就能赚钱”
- 有赞助或联盟关系就披露
- 读者不用你的链接，也能完成教程

推荐链接应该是顺手补贴成本，不应该变成文章存在的理由。

### 最后做模板和服务

等教程积累够多，可以把重复交付的东西整理出来：

- n8n workflow 模板包
- 服务器初始化脚本
- AstroPaper 中文启动包
- Cloudflare Pages 部署检查清单
- 小型自托管部署服务

这些比早期广告更贴近读者需求。读者不是来“看广告”的，他是来省时间、避坑、少走弯路的。

## 第一阶段看什么指标

第一阶段先不看收入，先看内容资产。

我会更关注这些指标：

1. 有没有 20 篇长期搜索文章
2. 每篇是否解决一个具体问题
3. 命令和配置能不能复现
4. 旧文是否定期复查
5. 搜索入口是不是逐渐稳定
6. 读者是否愿意收藏或回来查

这些比广告后台里的几分钱更重要。

## 我的判断

技术博客覆盖服务器成本，靠的不是一两个广告位，而是长期可信内容。

先把教程写扎实，让读者真的能照着做；再把常用脚本、模板和服务整理出来；最后才考虑广告、赞助或更完整的产品化。这个顺序慢，但不容易把站点做歪。
