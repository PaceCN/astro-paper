博客维护很适合交给 Agent 做一部分，但不适合从选题到发布完全自动化。

## 适合交给 Agent 的事

- 搜索近期文档和工具变化
- 整理关键词和选题
- 生成文章大纲
- 检查链接是否失效
- 检查 frontmatter、标题、描述、标签
- 根据模板生成初稿
- 对旧文提出更新建议

这些任务重复、耗时，而且可以通过检查清单约束质量。

## 不建议全自动发布的原因

技术博客最大的资产是可信度。全自动发布容易出现这些问题：

- 没有真实验证的配置
- 版本变化后内容失效
- 收益承诺写得过满
- 联盟链接披露不清
- 低质量 AI 水文影响搜索表现

所以更合理的方式是：Agent 产出草稿或 PR，人确认后合并。

## 推荐周流程

```txt
周一：选题和关键词研究
周二/三：草稿与实验
周四：技术验证和截图
周五：SEO、合规、链接检查
周末：人工审核后发布
```

## 本站的执行方式

这个项目会先把维护记录放在 `docs/` 目录里：

- `docs/PROJECT_LOG.md`：记录做过什么
- `docs/BLOG_OPS.md`：记录运营方向和维护原则

后续如果创建长期博客 Agent，它应该只负责草稿和检查，不直接发布到生产环境。
